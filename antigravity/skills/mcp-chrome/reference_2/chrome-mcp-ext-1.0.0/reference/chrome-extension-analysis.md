# MCP Chrome Extension (chrome-mcp-ext) 安全性分析報告

**審查目標**：針對 `chrome-mcp-ext-1.0.0` (MCP Chrome 擴充功能) 進行安全性檢查，著重於權限範圍、外部通訊機制，以及是否存在後門或資料外洩風險。

---

## 1. 權限與能力範圍 (Permissions)

透過分析 `manifest.json`，我們發現這個擴充功能要求了**非常巨大且全面**的權限：
*   **廣泛的資源存取**：`"<all_urls>"`（可讀寫所有網站的內容）。
*   **深度的瀏覽器控制**：`"debugger"`, `"scripting"`, `"tabs"`, `"webRequest"`, `"declarativeNetRequest"`, `"downloads"` 等。
*   **原生通訊能力**：`"nativeMessaging"`（用於與本地端的 `mcp-chrome-bridge` 溝通）。

**分析結論**：
這是一個具有**「上帝權限」**的擴充功能。它可以攔截網路請求、讀取任何分頁的內容（包含登入狀態、密碼、對話紀錄）、並透過 debugger 協議隨意注入 JavaScript。
**然而，這並非惡意行為，而是它存在的目的**——因為 MCP (Model Context Protocol) 的本質就是要讓 AI 代理（如 Cursor、Claude）能夠代替人類完整操控瀏覽器。

---

## 2. 外部通訊與資料外洩審查 (Data Exfiltration)

我們針對擴充功能打包後的程式碼（特別是 `background.js`）進行了靜態網路請求掃描：

1.  **無未知外部連線**：
    *   程式碼中沒有發現會將使用者資料偷偷上傳到任何第三方伺服器（如 analytics 追蹤器或惡意伺服器）的 `fetch` 或 `XMLHttpRequest` 呼叫。
    *   沒有建立隱密的 WebSocket 連線。
2.  **指令接收管道單一**：
    *   沒有使用 `chrome.runtime.onMessageExternal`，這意味著網頁上其他惡意腳本或**其他的擴充功能無法直接下達指令給它**。
    *   它**唯一**接收指令的來源，是透過 `chrome.runtime.connectNative("mcp_chrome_bridge")` 連線到您剛才安裝的本地 Node.js 程式。

---

## 3. 潛在風險與安全建議

這套擴充功能本身是**安全且沒有被植入後門**的，但因為它賦予了極高的控制權，在架構上會帶來以下固有的風險：

### ⚠️ 風險 1：AI 代理的暴走或越權 (AI Capability Abuse)
既然擴充功能可以讓 AI 控制瀏覽器，如果連接這個 MCP 的 AI 發生幻覺，或者被有心人士透過「提示詞注入 (Prompt Injection)」攻擊，AI 理論上有能力去讀取您的 Gmail、操作您的網路銀行，或刪除您的雲端檔案。
**防範方式**：
*   永遠只在**您能監控**的情況下使用 AI 瀏覽器自動化功能。
*   避免在使用 MCP 控制瀏覽器時，讓瀏覽器停留在含有機密資料或高風險操作（如銀行、支付）的分頁。

### ⚠️ 風險 2：本地橋接器的安全性
如前一份報告所述，擴充功能是聽命於本地的 `mcp-chrome-bridge`。如果您的電腦被駭客入侵，駭客就能透過 `127.0.0.1` 對這個擴充功能下達指令，進而控制您的瀏覽器並繞過所有網站的雙重驗證 (2FA)。

---

## 4. 總結

`chrome-mcp-ext-1.0.0` 在程式碼層面是**乾淨的工具程式**，沒有夾帶私貨或後門。它的危險性純粹來自於它所提供的「強大功能」。

建議您依照我稍早提供的**「載入未封裝項目 (Load unpacked)」**方式來安裝這個擴充功能，確保它永遠不會被自動更新覆蓋為惡意版本。在此前提下，只要您謹慎使用 AI，這套系統是安全的。
