# 發布前審查檢查清單

在每次向 Chrome 線上應用程式商店提交審查前，請逐一檢查此清單。每個項目都對應了常見的退件原因或發布失敗原因。

## Manifest 與擴充功能套件

- [ ] **manifest_version 為 3** — 新提交的擴充功能已不再接受 Manifest V2。
- [ ] **版本號已遞增** — 線上商店會拒絕上傳版本號 ≤ 目前已發布版本的套件。請使用語義化版本控制 (SemVer)：修正錯誤遞增 Patch，新增功能遞增 Minor，重大變更遞增 Major。
- [ ] **名稱與 CHROMEWEBSTORE.md 一致** — manifest.json 中的 `name` 欄位必須與您在商店資訊中填寫的名稱完全一致。
- [ ] **manifest 中的說明長度 ≤ 132 個字元** — 這是顯示在 `chrome://extensions` 中的簡短說明。它應該與您的商店簡短說明一致或接近。
- [ ] **ZIP 壓縮檔中沒有多餘的檔案** — 排除：`.git/`, `node_modules/`, `.env`, `*.map`, 測試檔案, 建置設定檔, `CHROMEWEBSTORE.md` 本身, `README.md`, `.DS_Store`, `thumbs.db`。建議使用建置腳本或類似 `.cws-ignore` 的排除機制。
- [ ] **ZIP 檔案大小在 2GB 以下** — 這是最大套件限制。大多數擴充功能應控制在 10MB 以下。
- [ ] **無絕對檔案路徑** — manifest.json 中的所有路徑必須為相對路徑。

## 權限宣告

- [ ] **最低權限原則** — 僅請求您確實需要的權限。`<all_urls>` 是一個敏感宣告。如果可行，請使用具體的主機權限，例如 `*://*.example.com/*`。
- [ ] **每個權限都有正當理由** — 檢查 CHROMEWEBSTORE.md 中的權限聲明部分。商店後台會要求為每個權限填寫聲明理由 — 您需要在提交時填寫這些內容。
- [ ] **優先使用 activeTab，而非 tabs + <all_urls>** — 如果您僅在使用者點擊圖示時才需要存取目前分頁，則 `activeTab` 才是正確的權限。
- [ ] **無多餘未使用的權限** — 如果您移除了某個使用到該權限的功能，也請一併將該權限從 manifest.json 中移除。殘留未使用的權限會導致退件。
- [ ] **主機權限 (host_permissions) 理由充足** — 說明哪些功能需要存取哪些網域，以及為什麼。

## 商店資訊內容

- [ ] **詳細說明非常具體** — 準確描述擴充功能的作用。不要使用含糊的行銷用語。審查團隊會仔細閱讀這部分。
- [ ] **單一用途非常聚焦** — 用一句話清楚說明核心功能。例如：「將書籤整理到分類資料夾中」，而不是「生產力提升工具」。
- [ ] **無誤導性宣告** — 不要宣稱擁有尚未實作的功能，也不要誇大效能宣告。
- [ ] **沒有關鍵字堆疊** — 不要在說明中不自然地重複關鍵字。
- [ ] **無商標侵權** — 除非獲得授權，否則不要在擴充功能名稱、說明或螢幕截圖中使用其他公司的名稱、標誌或商標。
- [ ] **聯絡信箱有效** — 商店頁面上顯示的聯絡信箱必須有人監管。Google 會將重要通知（下架、政策變更）發送到此地址。

## 圖形素材

- [ ] **商店圖示**：128×128 PNG，不可有透明度問題，在小尺寸下也必須清晰可讀。
- [ ] **至少 1 張螢幕截圖**：1280×800 或 640×400 像素。呈現擴充功能運作中的畫面。
- [ ] **螢幕截圖為最新狀態** — 與當前版本的擴充功能 UI 一致。過時的截圖可能會導致退件。
- [ ] **無誤導性截圖** — 螢幕截圖必須真實呈現擴充功能。
- [ ] **無手機/平板電腦樣機底框** — 除非該擴充功能確實能在這些裝置上運作。
- [ ] **小型宣傳方塊** (推薦)：440×280 PNG 或 JPEG。用於商店的主題推薦版面。

## 隱私權與合規性

- [ ] **資料收集聲明與實際相符** — 後台的資料使用勾選項目必須準確反映擴充功能程式碼的實際行為。不符 = 退件。
- [ ] **隱私權政策連結有效** — 親自點擊該網址確認。確認它可以正常載入且包含真實政策，而非 404 或預留位置頁面。
- [ ] **隱私權政策與聲明一致** — 政策文本必須與您在後台聲明表單中填寫的內容一致。
- [ ] **揭露 chrome.storage.sync 的使用** — 如果您使用 `chrome.storage.sync`，資料會被傳送到 Google 的伺服器。這算作將資料傳輸至裝置外。
- [ ] **禁止執行遠端程式碼** — 擴充功能不能執行遠端託管的程式碼。所有 JS 必須打包在擴充功能套件中。在執行階段不可從 CDN 載入腳本（Manifest V3 強制執行此規定，但仍請確認）。
- [ ] **無模糊處理程式碼** — 程式碼壓縮（Minification）是可以的，但禁止進行模糊處理（Obfuscation，故意讓程式碼無法閱讀），否則會導致退件。

## 功能完整性

- [ ] **功能運作正常** — 在 Chrome 中以未打包方式載入，測試所有功能。檢查主控台（Console）是否有報錯。
- [ ] **無當機或空白彈出式視窗** — 測試彈出式視窗、側邊欄、選項網頁、內容腳本。所有頁面加載都不應出現錯誤。
- [ ] **能在指定網站上運作** — 如果擴充功能是針對特定網站設計的，請確認它在這些網站的最新版本上能正常運作。
- [ ] **優雅降級** — 擴充功能應能處理邊緣情況（例如無網路、資料為空、限制網頁如 `chrome://` 頁面）而不會崩潰。
- [ ] **解除安裝乾淨無殘留** — 移除擴充功能後不應留有持續性的副作用。
- [ ] **沒有過度佔用資源** — 擴充功能不應明顯拖慢瀏覽速度。內容腳本尤其應保持輕量。

## 版本更新（針對已上架的擴充功能）

- [ ] **CHROMEWEBSTORE.md 的版本歷程已更新** — 新增一筆記錄，包含版本號、日期和變更摘要。
- [ ] **更新了「最後更新日期」** — 如果進行了任何面向使用者的變更。
- [ ] **說明中的功能列表已更新** — 如果新增了新功能。
- [ ] **權限聲明理由已更新** — 如果 manifest.json 中的權限有變更。
- [ ] **更新了螢幕截圖** — 如果 UI 有重大變更。
- [ ] **更新了隱私權揭露** — 如果資料處理方式有變更。

## 打包腳本

若要建立一個乾淨的 ZIP 套件以供送審，可以使用如下腳本：

```bash
#!/bin/bash
# package-extension.sh — 建立用於提交至 Chrome 線上應用程式商店的乾淨 ZIP 壓縮檔

EXTENSION_NAME="my-extension"
VERSION=$(node -p "require('./manifest.json').version")
OUTPUT="${EXTENSION_NAME}-v${VERSION}.zip"

# 移除舊套件
rm -f "$OUTPUT"

# 建立排除開發檔案的 ZIP 壓縮檔
zip -r "$OUTPUT" . \
  -x ".git/*" \
  -x "node_modules/*" \
  -x ".env" \
  -x "*.map" \
  -x "tests/*" \
  -x "__tests__/*" \
  -x "*.test.*" \
  -x "*.spec.*" \
  -x ".eslintrc*" \
  -x ".prettierrc*" \
  -x "tsconfig.json" \
  -x "package.json" \
  -x "package-lock.json" \
  -x "webpack.config.*" \
  -x "vite.config.*" \
  -x "rollup.config.*" \
  -x "CHROMEWEBSTORE.md" \
  -x "README.md" \
  -x "CHANGELOG.md" \
  -x ".DS_Store" \
  -x "Thumbs.db" \
  -x "*.sh" \
  -x "store-assets/*"

echo "已打包：$OUTPUT ($(du -h "$OUTPUT" | cut -f1))"
```

請根據您的專案客製化排除列表。關鍵原則是：僅打包 Chrome 執行該擴充功能所必需的檔案。
