# 隱私權政策指引

## 何時需要隱私權政策？

如果您的擴充功能符合以下情況，隱私權政策網址是**必要（Required）**的：
- 處理使用者的個人或敏感資料（如線上商店政策所定義）
- 使用了以下任何權限：`identity`, `cookies`, `webRequest`, `browsingData`, `history`, `bookmarks`, `topSites`，或 `<all_urls>` 主機權限
- 收集任何形式的分析數據或遙測數據
- 將任何資料傳輸到使用者裝置之外

對於所有擴充功能，即使沒有收集任何資料，也**推薦（Recommended）**提供隱私權政策。
這能展現專業性，並能避免審查人員質疑您的擴充功能，從而防止審查遭到延誤。

## 該託管在哪裡？

隱私權政策必須放在公開可存取的網址上。可選方案包括：
- **GitHub Pages**：免費且有版本控制。在 `docs/` 資料夾或分支中建立一個 `privacy.md`。
- **GitHub Gist**：快速且簡單。建立一個公開的 gist，並連結到原始碼（Raw）網址。
- **專案網站**：如果您有專案網站，可以新增一個 `/privacy` 頁面。
- **Notion / Google Sites**：免費的託管網頁，網址相當穩定。

避免將政策託管在隨時可能會關閉或變更的網址上。審查團隊會實際點擊該連結檢查。

## 政策中應包含什麼內容？

### 極簡版政策（不收集資料）

如果您的擴充功能確實不收集任何資料，政策可以很簡短：

```
[擴充功能名稱] 隱私權政策

最後更新日期：[日期]

[擴充功能名稱] 不會收集、儲存或傳輸任何個人資料或瀏覽資訊。所有資料均保留在您的個人裝置上。

此擴充功能不會使用 Cookie、分析工具或任何第三方服務。

若有任何疑問，請聯絡 [電子郵件信箱]。
```

### 標準版政策（有收集部分資料）

如果您的擴充功能會儲存或傳輸資料，請涵蓋以下主題：

1. **收集了哪些資料** — 請具體說明。「使用者偏好設定」是不夠的。
   應寫成：「您選取的佈景主題偏好設定（亮色/暗色）以及儲存的反白顏色。」

2. **資料如何儲存** — 僅儲存在本機？透過 `chrome.storage.sync` 進行同步？
   還是傳送到伺服器？

3. **為什麼收集這些資料** — 將每種資料類型與具體功能連結起來。

4. **第三方服務** — 如果您使用了任何 API（分析、身分驗證等），請寫出其名稱並提供其隱私權政策連結。

5. **資料共用** — 聲明是否與第三方共用資料。如果是，與誰共用、為什麼共用。如果沒有，請明確說明。

6. **資料保留期** — 資料會保留多久？使用者可以刪除它嗎？

7. **使用者控制權** — 使用者如何存取、匯出或刪除其資料？
   如果擴充功能有「清除資料」按鈕，請加以提及。

8. **政策變更** — 聲明如果做法改變，您將會更新政策，並說明將如何通知使用者。

9. **聯絡資訊** — 供使用者詢問隱私問題的信箱或網址。

### 範本

```
[擴充功能名稱] 隱私權政策

最後更新日期：[日期]

## 我們收集的資料

[描述收集的每種資料類型，以及需要該資料的對應功能。]

## 資料儲存方式

[描述儲存機制 — 僅限本機、同步儲存或伺服器端。]

## 資料使用方式

[描述每個使用情境。請與具體功能連結。]

## 第三方服務

[列出使用的任何第三方服務，並提供其隱私權政策連結。
若無，請寫：「此擴充功能未使用任何第三方服務。」]

## 資料共用

[聲明資料是否與他人共用。如果是，與誰共用、為什麼共用。]

## 資料保留與刪除

[資料保留多久，以及使用者該如何刪除它。]

## 本政策之變更

[本政策可能會在何時以及如何更新，以及我們將如何通知使用者。]

## 聯絡我們

[供隱私問題諮詢的電子郵件信箱或支援網址。]
```

## 常見錯誤

- **政策與資料使用聲明表單不符**：開發者後台的資料揭露表單與您的隱私權政策必須一致。如果表單勾選「不收集資料」，但政策中卻提到了分析數據，將會被退件。

- **政策內容過於含糊**：「我們可能會收集某些資料」是不可接受的，請務必具體說明。

- **連結失效**：如果您的隱私權政策網址回傳 404，該次提交將會自動被拒絕。請在提交前驗證連結。

- **遺漏資料類型**：如果您的擴充功能使用 `chrome.storage.sync`，該資料會傳輸到 Google 的伺服器 — 請務必揭露此點。如果您發出任何 `fetch()` 呼叫，也請揭露傳送了什麼。

- **沒有聯絡資訊**：線上商店要求提供使用者能就隱私問題與您聯絡的管道。請至少包含一個電子郵件地址。
