# 商店上架技巧與常見被退件原因

## 撰寫高效的商店說明

### 簡短說明 (最長 132 個字元)

這會顯示在搜尋結果和類別頁面中。這是您的電梯簡報。規則如下：

- 以動詞或擴充功能的功能開頭：「在所有網站上阻擋廣告」，而不是「廣告阻擋器」
- 具體詳細：「將選取的文字翻譯成 50 多種語言」，而不是「翻譯工具」
- 自然地包含主要關鍵字
- 不要把字數浪費在寫「Chrome 擴充功能」上 — 使用者早已知道這是擴充功能

**優良範例：**
- "一鍵儲存文章以供稍後閱讀。支援離線使用。"
- "將新分頁替換為顯示天氣與任務的極簡工作面板"
- "在任何網頁上反白標示並記錄註解。可將筆記匯出為 Markdown。"

**不良範例：**
- "Chrome 上最好的生產力工具！"（太含糊，純行銷用語）
- "幫助您把事情做得更好的擴充功能"（什麼都沒說明）
- "全新！適用於 Chrome 瀏覽器的超棒標籤管理器擴充功能工具應用程式"（關鍵字堆疊）

### 詳細說明 (最長 16,000 個字元)

線上商店會清除所有 Markdown 格式。請使用帶有換行的純文字。結構建議如下：

```
[一句話：此擴充功能做什麼用？]

主要功能
• 功能 1 — 簡要說明
• 功能 2 — 簡要說明
• 功能 3 — 簡要說明

如何使用
1. 點擊工具列中的擴充功能圖示
2. [下一步步驟]
3. [下一步步驟]

隱私安全
此擴充功能不會收集任何個人資料。您的 [資料類型] 會儲存在您的本機裝置上，絕不會傳輸到 any 伺服器。

權限說明
• 「讀取並變更您造訪的網站上的所有資料」— 用於 [特定功能]。
  此擴充功能僅在您 [觸發動作] 時才會啟用。

技術支援
發現錯誤？有任何建議？請傳送郵件至 [信箱] 或在 [網址] 提出 Issue。

版本 [X.Y.Z] — [最新版本的簡要變更日誌]
```

### 為什麼這個結構有效

1. **一句話開頭** — 審查人員和使用者都會先掃描第一行。讓它發揮最大作用。
2. **功能列表** — 使用者會尋找具體能力。純文字的項目符號（•）呈現效果很好。
3. **如何使用** — 減少支援請求，並向審查團隊證明擴充功能確實可以運作。
4. **隱私區段** — 預先解答使用者對權限的疑慮，建立信任感。
5. **權限解釋** — 使用者在安裝時會看到權限警告。如果您在說明中先進行解釋，他們放棄安裝的機率會大大降低。
6. **支援資訊** — 線上商店政策要求提供（「有意義的客戶支援」）。
7. **最新版本備註** — 顯示此擴充功能正持續維護中。

### 單一用途宣告 (Single Purpose Statement)

這是在開發者後台填寫的，不會顯示給一般使用者。審查團隊會非常仔細閱讀。它必須是一句話，描述擴充功能狹窄且聚焦的核心用途。

**已核准的範例：**
- "將網頁上反白標示的文字儲存到本機閱讀清單"
- "將新分頁替換為可自訂的工作面板"
- "在網站上阻擋 Cookie 同意橫幅"

**遭退件的範例：**
- "改善您的瀏覽體驗"（過於含糊）
- "生產力與整理工具"（範圍過廣）
- "反白標示文字、儲存書籤、管理分頁並阻擋廣告"（非單一用途）

如果您的擴充功能可以做很多事情，請專注於最核心的功能。次要功能可以在詳細說明中提及。

## 常見的被退件原因

### 1. 權限過大 (Excessive Permissions)

**問題現象：**「您的擴充功能請求了超出其所需的權限。」

**修正方法：**
- 將 `<all_urls>` 替換為特定的主機匹配模式
- 如果點擊時僅需要存取當前分頁，請將 `tabs` 替換為 `activeTab`
- 移除未使用的權限
- 確保每個權限都有明確的聲明理由

### 2. 缺少或不適當的單一用途宣告

**問題現象：**「您的項目沒有單一、明確的用途。」

**修正方法：**
- 重寫單一用途欄位，使其範圍變窄且具體
- 如果擴充功能真的做了太多不相關的事，請考慮拆分成多個擴充功能

### 3. 說明或功能具有誤導性

**問題現象：**「您的擴充功能未提供所述的功能。」

**修正方法：**
- 確保說明中列出的每項功能皆能正常運作
- 移除關於尚未開發功能的宣傳
- 除非有據可查，否則不要使用最高級形容詞（如「最好」、「最快」）

### 4. 隱私權政策問題

**問題現象：**「您的擴充功能需要隱私權政策。」或「無法存取您的隱私權政策網址。」

**修正方法：**
- 將隱私權政策託管在穩定、公開的網址上
- 確保該網頁不需登入即可瀏覽
- 確保政策涵蓋擴充功能實際收集的所有資料
- 讓隱私權政策與後台的資料使用聲明表單保持一致

### 5. 侵犯商標權

**問題現象：**「您的擴充功能未經授權使用了受商標保護的內容。」

**修正方法：**
- 不要在擴充功能名稱中使用其他公司的商標名稱（例如：「YouTube 下載器」）
- 不要使用暗示官方關聯的標誌或品牌顏色
- 使用通用術語：例如「適用於 [網站] 的影片下載器」可能可行，但仍請確認該網站的服務條款

### 6. 程式碼可讀性（模糊處理）

**問題現象：**「您的擴充功能包含模糊處理的程式碼。」

**修正方法：**
- 程式碼壓縮（Minification）是允許的，但模糊處理（Obfuscation）則被禁止
- 如果使用打包工具（webpack, rollup, vite），請確認輸出檔案沒有包含原始碼對照表（source maps），且輸出僅做壓縮而非模糊化
- 不要使用字串編碼等技巧來隱藏程式碼意圖

### 7. 執行遠端程式碼 (Remote Code Execution)

**問題現象：**「您的擴充功能執行了遠端託管的程式碼。」

**修正方法：**
- 將所有 JavaScript 打包在擴充功能套件中
- 在執行階段不可從 CDN 載入腳本
- 不要將 `eval()` 或 `new Function()` 與遠端內容搭配使用
- 從 API 獲取 JSON 資料是可以的；但獲取並執行 JS 則不被允許

### 8. 使用者資料揭露不符

**問題現象：**「您的擴充功能的資料使用情況與您的聲明不符。」

**修正方法：**
- 審查每個 `fetch()`, `XMLHttpRequest` 和 `chrome.storage.sync` 呼叫
- 請記住，`chrome.storage.sync` 會將資料傳輸到 Google 的伺服器 — 這必須予以宣告
- 如果您使用了任何分析套件（即使是自行託管的），也請進行宣告
- 如果您將錯誤記錄回傳給外部服務，請進行宣告

## 被退件後的處理

當擴充功能被退件時：

1. 仔細閱讀退件郵件 — 郵件中會指明違反了哪項政策
2. 在 CHROMEWEBSTORE.md 中記錄退件原因和採取的修正方案
3. 對擴充功能程式碼或商店資訊進行必要的修改
4. 對照發布前檢查清單重新驗證
5. 透過開發者後台重新提交
6. 註：重複違反政策可能會導致帳戶被停權

## 審查時間線

- 首次提交：通常需要 1-3 個工作天，有時可能更長
- 現有擴充功能更新：通常較快，通常在 24 小時內
- 快速審查：官方未提供此服務；保持良好的無違規紀錄有助於加快審查速度
- 延期發布：您可以選擇在審查通過後手動發布，這讓您能掌控上架時機。審查通過後必須在 30 天內發布。
